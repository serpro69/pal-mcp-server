# Implementing config-only clink clients

Use the [two manifests and contract](./design.md#two-complete-manifests) as acceptance fixtures. Exercise them through clink's MCP entry point using small local executables. Keep the JSON files in test fixtures so the default installation continues to advertise only the shipped clients.

## Resolve a custom manifest

Make discovery and reading strict in [the registry](../../../../clink/registry.py). Today `_iter_config_files` can silently skip an invalid explicit source, and `read_json_file` returns `None` on decode and I/O errors. A nonempty `CLI_CLIENTS_CONFIG_PATH` must designate a readable JSON file or a listable directory. Surface enumeration errors and dangling JSON-file symlinks. A readable directory with zero matching files contributes no definitions. Preserve source precedence, sorted directory order and the optional personal directory. Do not require installed executables to load manifests.

Read each selected file as UTF-8 JSON and require a nonempty object. Reject duplicate member names before converting object pairs to dictionaries, so a repeated permission field cannot silently replace the first value. Treat read/decode errors, empty files, `{}`, non-objects and field or resolution errors as fatal. Report the path and JSON line/column for syntax errors, the duplicate key or field location for validation, or a short read/encoding reason. Exclude input values and unsanitized exception chains. Leave the shared reader's other callers alone.

Build a candidate registry and publish it only after every discovered file succeeds. A damaged later override fails startup even when its client name cannot be recovered. Log the safe diagnostic through PAL's startup logger before propagating the error. [Server initialization](../../../../server.py) constructs clink before the MCP handshake, so the operator must use MCP host stderr or the main server log to diagnose it. Do not serve an earlier definition after a failed startup.

Branch on the normalized name before reading internal defaults. A shipped name follows the built-in resolution path. Reject an explicit `custom` adapter on a shipped name. An unknown name takes the generic path only after validation. Preserve complete-file replacement and role path resolution.

In [the models](../../../../clink/models.py), validate generic input before the legacy validators coerce it. Require the six top-level keys in the examples. Accept only the documented optional fields (`env`, `working_dir`, `additional_args`, `model_args`, `default_model`, `roles`, `timeout_seconds`, `history_token_budget`). Close the generic role, transport and output objects to unknown keys. Require actual arrays of strings for argument lists and passthrough names. Reject invalid environment names (empty, containing `=` or NUL), NUL in static process arguments or environment values, blank/control-bearing client or role names, and a command that fails tokenization or yields an empty executable. Reject `output_to_file` and runner overrides on generic clients. Preserve the shipped manifests' existing field and coercion rules.

Accept prompt flag names matching `-{1,2}[A-Za-z][A-Za-z0-9_-]*` in full. This includes `-q`, `-question` and `--question`. Emit the declared spelling. Reserve both dash spellings of the same **whole name**, bare or followed by `=`, across command-prefix, static, role, mode and model option tokens. Reject a configured `--` terminator in flag mode. With `-q`, `-q=x` is reserved and `-quiet` is a distinct name. PAL cannot infer vendor aliases, clustered flags or concatenated short-option values. The operator must keep those alternative spellings for the prompt out of static arguments. [Go flag syntax](https://pkg.go.dev/flag#hdr-Command_line_flag_syntax)

A JSON path contains one or more nonempty string keys. Dots in keys are literal. Text output takes no path. The failure hint is one nonblank line of at most 240 characters, suitable for returning to callers. Accept the optional strict boolean `custom.log_stderr_on_failure` with default false. Pass a typed generic protocol to the runner so client-supplied strings cannot select Python classes.

Create `systemprompts/clink/generic_default.txt` in this slice. Resolve it directly from `BUILTIN_PROMPTS_DIR` for each generic role without an explicit prompt, including a synthesized default role. Explicit prompt paths retain the existing manifest-relative lookup. Record only the new prompt's digest in the [prompt baseline](../../../../tests/fixtures/tool_surface_baseline.json). The [surface test](../../../../tests/test_tool_surface.py) checks the complete prompt path set as well as historical digests and schemas.

The independently developed slices must reject an option they cannot yet honor before spawning, including an opt-in diagnostic request until its file-only sink is implemented. Release once both complete manifests run through clink and the final verification task passes.

Verify a missing explicit source, a missing optional personal directory, and a valid earlier definition followed by malformed JSON, `{}` or a field-invalid replacement. For syntax damage, use an isolated server startup to observe exit before handshake and the filename and position on stderr and in the main log. Check field paths separately without exposing manifest values. A valid generic client with an absent executable still appears in the `cli_name` enum and in provider-free `listmodels` with `executable_found=false`. Cover valid built-in overrides and the stock surface.

## Run a text client safely

Fix the shared lookup in [availability](../../../../clink/availability.py) for discovery and invocation. Anchor a relative command containing a separator to PAL's startup cwd. Look up a bare command on the filtered, override-aware PATH, resolving relative search entries against that same cwd, including an empty entry where it denotes the current directory. On Windows use the child environment's case-insensitive PATH and PATHEXT, including operator overrides, and apply the batch restriction to the extension actually selected. Avoid mutating the server environment during lookup. Return an absolute executable path, preserving symlink spelling. Pass that value as argv[0] to [the base agent's spawn](../../../../clink/agents/base.py), keeping the selected child cwd and remaining operands as configured. Repeat lookup at execution so uninstalling a CLI after discovery produces a normal missing-executable error. Interpreter launchers should specify an absolute path for an operator-owned script. [Python subprocess path resolution](https://docs.python.org/3/library/subprocess.html#popen-constructor)

In both prompt preparation entry points in [the clink tool](../../../../tools/clink.py), choose generic guidance using the resolved client. Omit the unconditional repository, terminal and web claims, including the closing tools instruction. An explicit role replaces the fallback and still receives neutral guidance, file references, history, user request and edit policy. References supply paths and metadata. A text-only client needs the caller to supply any necessary contents. Treat a role file that disappears or becomes unreadable after startup as a pre-launch validation error. Keep the shipped adapters' role text and guidance.

Reuse command assembly, environment filtering and timeout/cancellation. Bind the generic parser per resolved client. Preserve the order of static, model, mode and role arguments. Validate the effective default argv for each role, including command-prefix and safe arguments, against PAL's known write-enabling options. Check the prompt flag and retain existing safe/edit bucket validation. Unknown vendor permissions remain the operator's responsibility.

Gate unsupported edit requests and scoped paths before execution. Feed the prepared prompt through stdin exactly once. A zero exit and nonblank stdout return the original decoded text with its whitespace. Generic parsers supply empty native metadata. Keep clink's existing response cap, history commit and continuation behavior. Distinguish validation, lookup, launch, timeout, exit and parse failures. Append the configured hint and log the client, stage and available exit code. Return only the executable name in the display command. Use the display form from the first subprocess debug log onward. Exclude raw child streams from generic MCP metadata on every path.

The generic runner must enforce a byte limit while reading. The current `limit=` on `create_subprocess_exec` controls the stream reader's buffering, and `communicate()` still accumulates to EOF. Feed stdin and drain both pipes concurrently under the existing timeout. Count bytes independently, accept exactly `DEFAULT_STREAM_LIMIT` per stream (10 MiB), and on the first excess report an output-limit error, suppress excerpts and stop the child. Join/cancel the I/O tasks, reap before scratch cleanup and preserve caller cancellation. Cleanup must also discard or close remaining pipe data without an unbounded second read. Leave native runners on their current lifecycle. Decode successful generic stdout as strict UTF-8. Diagnostic stderr may use replacement characters.

Preserve existing error contracts before client selection (invalid request, unknown continuation, busy thread). After selection, attach the generic hint to client-specific failures and retain existing directory error metadata and recovery guidance. Once the child has succeeded, retain clink's existing `history_saved=false` handling for memory persistence failures. Do not reclassify those replies or replay the CLI.

Verify discovery and the absolute launch path with distinct server and project directories, for both an explicitly relative command and a relative PATH entry. Inspect stdin with the neutral fallback and a supplied role. Cover edit selection, filtered credentials, continuation, malformed UTF-8 and overflow on either pipe. For overflow, observe the child being reaped and scratch cleanup and unchanged history. Reuse the existing cancellation checks on the new I/O path.

## Deliver flag prompts and extract JSON

Build the entire static argv first, append the declared flag and complete prepared prompt as two elements, and deliver EOF on stdin. Reject U+0000 anywhere in the assembled flag value before spawning. Return the client name, validation reason and configured hint. Stdin can carry a NUL byte. Preserve agy's structured stdin override. Reject Windows batch launchers for flag delivery. Document that a native launcher must preserve argument boundaries all the way to the CLI. Command-string wrappers such as `cmd /c`, `powershell -Command` and `sh -c` are unsupported. A native interpreter invoking an absolute script path as a file is suitable when the script forwards argv literally. PAL cannot audit arbitrary wrappers. [Existing launcher guidance](../../../tools/clink.md#choosing-the-cli-model)

Handle POSIX `E2BIG` and Windows command-length errors (including error 206 for an oversized command) as launch failures. Report the client and hint, keep history intact and avoid replay. Advise shortening the current request or starting a new conversation with a summary. For future sessions, recommend lowering the flag client's `history_token_budget` and restarting PAL. The 16,384-token default budgets history alone. Current input, the role and other prompt sections also consume argv space. A restart invalidates old continuation IDs, and even a small history budget cannot make an oversized current request fit.

Linux limits one string to 32 pages, including its terminator (128 KiB on a 4 KiB-page system), and also limits combined argv and environment size. Windows limits the entire quoted command line to 32,767 UTF-16 code units including its terminator. Other systems have their own aggregate limits. Treat the OS result as authoritative and test its error mapping independently of the build host's limit. [Linux execve(2)](https://man7.org/linux/man-pages/man2/execve.2.html) · [Windows CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw)

For JSON output, decode a single stdout document, visit each configured object key and return the exact selected string. Reject multiple documents, malformed output, missing keys, non-object intermediates and non-string, blank or non-UTF-8-encodable leaves (including a lone surrogate decoded from a JSON escape). Include the configured field path and reason in the diagnostic. Reject a non-encodable prepared prompt before either transport starts. Nonzero exit takes precedence over parsing. All four transport/output combinations are independent.

Verify a multiline Unicode prompt with spaces, quotes and a leading dash arrives as one value with empty stdin. Check NUL rejection before spawn, the stdin control, and an oversized follow-up with unchanged history and actionable recovery. Exercise nested-key extraction and the named failure for a missing field.

## Enforce the selected workspace

Use the selection returned by [the directory resolver](../../../../clink/working_directory.py) in `CLinkTool._execute_coordinated`. Apply `any` or `project` immediately after selection. Reject scratch for `project` before launch using the existing validation envelope. Preserve the launch spelling and canonical identity. Any existing selected project directory passes PAL's policy. Repository and trust checks belong to the native CLI. Report their failures with the client hint and the usual exit diagnostics.

| Selection | Recovery |
| --- | --- |
| New conversation would use scratch | Supply `working_directory_absolute_path` now, or set manifest `working_dir` and restart PAL for future calls. |
| Existing conversation is bound to scratch | Supply `working_directory_absolute_path` on this follow-up with the same continuation ID. Selection promotes scratch to project only after a successful exchange. An omitted request directory reuses saved scratch even if the manifest supplies a directory. |
| Existing conversation is bound to a project | If the CLI rejects that directory, its hint can help fix access and retry in place. To select a different project, omit the continuation ID and start a new conversation with the desired directory. An explicit conflicting path still gets the resolver's existing new-conversation error. |

Verify new and inherited scratch recovery, success-only promotion, an ordinary project directory and a native CLI failure in a bound project. Observe whether the configured CLI launched and whether the original binding survived.

## Private failure diagnostics

When `log_stderr_on_failure` is true and complete stderr is available, send a bounded excerpt only to PAL's main rotating file. Use a record scoped to this invocation and a file-only route. Before taking the last 2,048 characters, redact the literal prepared prompt and nonempty values from the effective child environment, including shared proxy variables. Match against the original text so overlapping values cannot leave part of a longer known secret behind. Escape line breaks and control characters, bound the final rendered excerpt and mark truncation. On success, timeout/cancellation without complete diagnostics, overflow or filtering failure, omit the excerpt.

Account for sink failure as well as propagation. Python's standard rotating handler can send a failed record and its arguments to stderr via `handleError`. For an excerpt record, suppress that fallback even on emit/rotation failure. Preserve normal logging for unrelated records. A logging failure must leave the original CLI outcome intact. Check default-off and opt-in calls, an echoed prompt/credential spanning the truncation boundary, and a failing file sink. Inspect the main log, activity log, host stderr and MCP result. Only a successful write to the main log may show the filtered excerpt. Partial echoes, transformed values and secrets independently obtained by the CLI can remain sensitive.
