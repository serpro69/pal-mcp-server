# Issue 33 design review resolution

All 15 findings called for a document change. The 12 entries below group findings that share a fix. R1 numbers follow the bullets in the first review from top to bottom. R2 uses the second review's numbering. Evidence refers to the code at `c61dfe9`. The design and tasks describe future implementation.

| R1.1 + R2.2 · Startup and replacement | `ALL_TOOLS` constructs clink at import, and clink immediately loads its registry. A nonempty invalid definition can stop the server. The shared JSON reader catches decode and I/O errors, and the registry skips falsey data, so a damaged or empty override can also leave an earlier definition active. Both outcomes exist today. [Startup](../../../../server.py) · [Registry](../../../../clink/registry.py) · [Reader](../../../../utils/file_utils.py) | Every discovered file must validate before the registry is published. The whole server stops before handshake on failure, even if the intended client name cannot be recovered. The host's stderr and PAL's main log identify the file and failure location. Task 1 covers a damaged later override and a valid control. |
| R2.1 · Executable identity | On this checkout, looking up an explicit relative command and looking up its bare name on a relative PATH both returned a relative pathname. The base agent places that result in argv[0] and supplies a separately selected child cwd. The impact depends on platform and path spelling. [Lookup](../../../../clink/availability.py) · [Launch](../../../../clink/agents/base.py) | Anchor lookup to PAL's startup directory and launch the absolute result. Task 2 checks both relative cases with separate server and project directories. Interpreter script operands have an explicit operator contract. |
| R1.2 · Flag-mode capacity | The user-input default is 60,000 characters. The separate history default is 16,384 estimated tokens. Role text and history enter the prepared prompt before launch. The OS limits use different units and include other overhead. Retrying unchanged input can repeat the failure. A shorter request can still fit on the same thread. [Input limit](../../../../config.py) · [History budget](../../../../clink/constants.py) · [History rendering](../../../../clink/conversation.py) | Specify OS error handling, a shorter retry or fresh summarized thread, and a smaller manifest budget for future sessions. Restart loses continuation IDs. The guide must give Linux and Windows limits with their units. [Platform details](./implementation.md#deliver-flag-prompts-and-extract-json) |
| R1.3 · Operator diagnostics | The ordinary error builder copies native stdout and stderr into metadata. The root logger writes to both stderr and the main file. Simply enabling debug logging would give an operator neither the proposed privacy boundary nor a controlled native diagnostic. [Error metadata](../../../../tools/clink.py) · [Handlers](../../../../server.py) | Explain the exposure of history and credentials. Default to stage, reason and hint. Add explicit per-client opt-in for a bounded, filtered failure stderr tail in the main file only. Verify all output sinks and document residual risks. |
| R1.4 + R2.6 · Workspace policy and recovery | Issue #33 asks about repository requirements. Its examples establish no need for PAL to run Git independently. A bound project rejects a different requested path. [Issue](https://github.com/serpro69/pal-mcp-server/issues/33) · [Directory selection](../../../../clink/working_directory.py) · [Git ownership policy](https://git-scm.com/docs/git-config#Documentation/git-config.txt-safedirectory) | Ship `any` and `project`. ## Implementation readiness

All earlier resolutions still apply. The final pass closed four gaps between their intent and the implementation path.

- **Configuration and discovery.** Strictness starts when PAL selects the source. The plan distinguishes missing explicit configuration, an absent personal directory and a missing executable. It covers duplicate permission keys, invalid process strings and the effective Windows executable search environment. [Registry plan](./implementation.md#resolve-a-custom-manifest)
- **Role and fixture availability.** The neutral role ships in Task 1 with its prompt digest. The acceptance harness needs an explicit custom-manifest path because its vendor setup rewrites commands. Task 6 uses named fixtures on PATH and checks the role in an installed server. [Acceptance plan](./implementation.md#operator-documentation-and-release-checks)
- **Subprocess and history.** The current runner reads both pipes to EOF. The generic transport caps each stream during I/O, preserves timeout/cancellation cleanup, and validates the parsed answer before committing history. Client-specific diagnostics start after selection. A persistence warning after native success keeps its existing meaning. [Execution plan](./implementation.md#run-a-text-client-safely)
- **File-only logging.** An ordinary rotating handler's error path can print the record to host stderr even with logger propagation disabled. Task 5 owns the private sink and covers write/rotation failure, filtering and the four observable output destinations. [Diagnostic plan](./implementation.md#private-failure-diagnostics)
